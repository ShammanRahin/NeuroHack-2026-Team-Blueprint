### 3. Method and validation strategy
Text is normalised (NFKC, zero-width removal, homoglyph/leet mapping outside Bangla tokens, spaced-letter rejoin). Features: char 2-5 and word TF-IDF, ~66 hand-written lexicon features built from the labelling guide (English, Banglish, Bangla), obfuscation statistics of the raw text, and (GPU configs) Banglish-aware e5 sentence embeddings plus cosine similarity to trilingual label descriptions. One logistic-regression head per task (label, action, six binary technique heads). Final config (`preli_final`): these linear probabilities are averaged with a Banglish e5-small encoder (weight 0.7 encoder / 0.3 linear; 0.5 was fixed in advance and scored 0.888 public, 0.7 scored 0.891, chosen with one extra submission) fine-tuned for one pass on the 1M synthetic rows (label smoothing 0.1, dropout, weight decay; 8% of generator templates held out entirely and used for early stopping and for the Task D temperature, so confidence is calibrated on unseen phrasings). The encoder never sees test text except to predict it (direct inference, permitted by the organisers' clarification of 27 Nov). A decoder applies the guide's structure: classes 0/5 get techniques NONE and action 0, every scam gets at least one technique and a non-zero action, class-conditional priors smooth techniques/actions, noise-only text is routed to class 0.
Training data: the 86 real rows (+ corrupted copies, Bangla<->Banglish transliterations, conversation views) and code-generated synthetic messages written from the labelling guide (templates plus a hook+request composer covering all classes, techniques, actions, registers, languages, code-mixing and hard negatives). Test text is never used for fitting anything.
Validation: (1) train on synthetic rows only and score all 86 real rows with the competition's composite (macro-F1 A/B/C, robustness on corrupted copies, Brier); (2) hold out whole synthetic templates to measure generalisation to unseen phrasings; (3) earlier ablations used repeated StratifiedGroupKFold over near-duplicate groups on the 86 rows plus language/register shift holdouts.

### 4. Reproduction notes
Run all cells top to bottom; the notebook writes the project files and runs `python -m src.run exp=<config>`. No LLM is used, so there is no sampling non-determinism; the synthetic generator, augmentation and models are seeded (seeds in the config section). Approximate runtime: 25-40 min on CPU for the TF-IDF config, plus ~10-15 min for embeddings on a T4 for the GPU config; the final config adds ~30-50 min of encoder fine-tuning on 2x T4 (capped at 50 min). Fine-tuning on GPU is seeded but not bit-exact across hardware. Output: /kaggle/working/outputs/<exp>/submission.csv.
